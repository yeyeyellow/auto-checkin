# 签到恢复机制（2026-10-13）

两个论坛使用本目录的运行器与 Windows 系统互斥。必须保留整个 `auto_checkin` 目录结构，不能只移动其中一个论坛目录。

## 自动运行

- 2026-10-13 修复登录周期误判：使用 Windows 最近一次系统启动事件的固定标识，不再要求 `LastBootUpTime` 字符串完全一致。系统校时、睡眠恢复不会因此取消当天补试；真正重启和跨日仍须由登录入口建立新周期。当天旧记录只有启动时间偏差小于 1 秒才允许迁移，迁移后只比较固定标识。无法读取启动事件时记录 `BOOT_ID_UNAVAILABLE` 并由恢复任务稍后再检查。
- 保留启动文件夹里的入口：当前用户登录后等待 180 秒，隐藏运行。
- Windows 登录入口开启当天签到周期。Windows 任务 `LaowangForumCheckinRecovery` 和 `Hjd2048CheckinRecovery` 每 5 分钟仅检查这个周期的到期补试；没有当天登录周期时跳过，跨日不自行启动新签到。睡眠恢复可继续当天已经开启的补试，不创建新周期，不唤醒电脑，不需要 Codex 打开。
- 恢复入口通过 WScript 隐藏 PowerShell；Chrome 始终无头。登录后头 3 分钟通过当前桌面 Explorer 创建时间保护，重启 Explorer 可能延后首次检查。
- 同一天、同一会话的成功已经两次经论坛确认后，后台检查直接跳过，不再启动 Chrome。登录会话变化后重新核实。
- 启动浏览器后先通过同一浏览器会话 GET 本站首页，确认成功响应、同站地址、HTML 内容且非空，再读取本人登录与签到状态。每个站点分别判断，一个不可访问不阻塞另一个。可访问性失败不计实际签到尝试。
- 断网、服务器错误、浏览器关闭、加载超时和低置信度图片：当天先快速尝试最多 10 轮，失败后等待 20 秒再尝试下一轮，成功立即停止。整个快速阶段持有系统互斥，每轮新建浏览器、先读取本人签到状态、再获取新验证码，并分别保存证据。每轮开始前保存 `rounds`（包括可访问性失败），进程中断或恢复任务再次运行不会重置十轮上限；旧记录从升级后的首轮开始计数。
- 十轮仍失败后，按 2、5、10、15 分钟逐步延后，后续每 30 分钟补试，在当前登录周期当天持续尝试。签到提交结果不确定和未分类错误直接转入分钟级查证，不快速重复提交。慢速检查频率会带来最多约 5 分钟额外延迟，睡眠/离线时可能更久。快速阶段采用 10 分钟软期限和 11 分钟看门狗；单轮过慢、接近期限时，剩余快速轮次由恢复任务继续。
- 网站明确限流后等待 30 分钟；回复结果不明时每 30 分钟只查询原帖，找到本人当天回复后继续签到，不再次发布。登录过期、无法确认安全表单、记录损坏仍记录需要处理。重新登录改变会话后重新核实登录故障。
- 2048 按发表时间选最新普通主题，排除置顶；不要求帖子当天发布，但本人回复仍按当天核实，每个账号每天最多一次自动回复。
- 已经核实成功并保存 CONFIRMED 的当天本人回复直接复用，不在每轮重复查找；只有 PENDING 记录需要后续查证。

## 中断与提交安全

互斥由 Windows 持有，Node 管道关闭或系统重启后释放；原有 `run.lock`、`run.lock.recovery` 文件不再参与判断。PowerShell 互斥辅助进程检查拥有者存活及创建时间，签到及登录入口均在 11 分钟期限后终止该进程树。外层运行器提供 735 秒超时保护，Windows 恢复任务期限为 14 分钟；每 5 分钟检查的频率不变，已运行任务忽略重复启动。

每一步立即追加运行日志，开始前原子写入当日 RUNNING 记录。上次被重启打断时，补试会先读取论坛实际状态。签到提交响应丢失后不再次点击，当次及下次均以论坛状态查证；只有两次本人账号签到状态一致才记成功。

论坛自己的提交后跳转若打断状态查询，等待页面加载后只重新读取一次状态；不再次提交签到或回复。持续无法确认时仍保留失败记录，转入慢速查证。

回复提交之前原子写入 PENDING 意图。当响应丢失后，只查询原帖子，最多查 3 页；核对本人、日期、正文。无法证明成功时保留 PENDING 并停止发布。跨午夜或运行中账号变化会停止旧流程。这样可能需要人工查证，但不会用重复发帖解决不确定性。

会话、回复记录、每日控制和结果采用临时文件写完、同步、替换；遇到 Windows 短时文件占用有限退避，不删除旧文件。会话保留完整备份，损坏时恢复后仍必须经过论坛登录状态校验。

2048 的明亮图片增加高阈值描边回退；至少两个高阈值定位一致且各自达到原置信度门槛才采用。失败图片及几何参数按运行保存，不被后续成功覆盖。尚未覆盖所有真实验证码类型。

## 查看与操作

每个论坛自己的 `artifacts` 下：

- `startup.log`：后台启动及分步输出。
- `runs/<运行编号>/events.jsonl`、`result.json`：每次实际尝试的分步证据和结果；失败截图与验证码素材也保存在该次目录。
- `last-attempt.json`：最近一次实际尝试开始时的记录，RUNNING 不代表目前进程仍在运行。
- `last-result.json`、`last-success.json`：最近结果与最近一次经论坛确认的成功分别保存。
- `attention.json`：需要处理的失败；成功后写 `attention: false`。不自动打开日志或弹窗。
- `startup-errors/`、`last-startup-error.json`：获取互斥前的初始化失败单独记录，不覆盖已核实的签到结果；冷启动等待上限 45 秒。
- `days/YYYY-MM-DD.json`：香港时区的实际签到次数 `attempts`、含网络预检的轮数 `rounds`、下次补试时间、成功状态，用于长期统计。

在 `auto_checkin` 目录执行：

```powershell
# 验证与观察统计；自动成功与手动补救分别计数，满 30 个有运行记录的日期才标记样本就绪

# 重新安装恢复任务（安装前验证同名任务属于本项目）

```

手动运行仍可用各项目 `npm run checkin`；`node checkin.mjs --force` 仅用于人工审查后的再次核实，可越过当日次数和停止标记，仍不能越过回复 PENDING 或未知页面保护。各项目 `remove-startup.ps1` 同时删除自己的启动入口及恢复任务，保留会话和日志。
